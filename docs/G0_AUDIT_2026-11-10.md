**Scope:** Read-only architectural/math review, deterministic fixtures, tests, a minimal front-end critical-path fix. **No orders, trades, paid infrastructure, credential changes, or speculative production math rewrite.**

## Release-gate verdict

**G0 substantially inspected, not G1–G7 production-certified.** The app has meaningful working research, guarded quote handling and paper workflows. The current fee model is explicitly a conservative simulation; it cannot be promoted to an exchange-exact fee or verified net-edge calculation. Market-specific tick-grid validation is also missing. A prospective audited out-of-sample track record is not established by unit tests or retrospective experiments.

## Highest-priority quantitative discrepancies

1. **Fee precision and per-order rounding — P0 before quoting an exchange-exact net edge.** `web/lib/workspace/execution-curve.mjs` and `web/public/dashboard/paper.js` round each modeled depth level upward to **$0.01**. Current Kalshi documentation defines a **$0.000001**-granularity trade fee, a balance-precision rounding component ($0.0001 direct / $0.01 non-direct), and an order-level rounding-fee accumulator/rebate across fills. The model's current single-level result is therefore not equal to the exchange *trade-fee component*: at 0.10 contracts × $0.50, `executionCurve` gives **$0.010000**, while a 0.07 × q × p × (1-p) trade fee rounded to six decimals is **$0.001750**. For 100 contracts × $0.9999, model **$0.010000** vs trade component **$0.000700**. **These are not necessarily exchange net fees:** member precision and order history must be incorporated before comparing final wallet debits. Also confirm market/series fee overrides before calling a coefficient verified. Official source: https://docs.kalshi.com/getting_started/fee_rounding.
2. **Market-specific tick and decimal grid — P0 before generating actionable quotes.** The feed parses fixed-point decimal strings as JavaScript `Number` and `execution-research.mjs` computes candidate inventory bids/asks by `floor/ceil(price × 100) / 100`. There is no `price_ranges` validation in this code path. This assumes a one-cent price grid and can reject, miss or invent tick validity on sub-cent markets. Preserve integer-scaled fixed-point prices and validate against current per-market `price_ranges`/quantity constraints rather than globally rounding to cents. Official reference: https://docs.kalshi.com/getting_started/fixed_point_migration.
3. **Prospective evidence and fill realism — P1.** The source explicitly samples at most one book snapshot/second per ticker (top 100 levels), not all events. Historical replay and retrospective holdouts cannot by themselves establish achievable returns, queue priority or executable edge. Gate positive ROI claims on timestamped, immutable forward signals, later independent outcomes, explicit transaction costs, non-overlapping event folds and latency/slippage sensitivity. See `web/tests/test_forward_collector.py` and `web/docs/FEATURE_REVIEW.md`.
4. **Assumed model coefficients — P1.** `web/ui/execution-state.mjs` falls back to 0.07 if fee metadata is absent. `execution-service.mjs` labels that state as unverified and withholds released settlement decisions, correctly, but downstream copy and screening must never imply a verified net after-cost opportunity from such a fallback.

## Critical rendering path: change applied in this patch

- The user-supplied Lighthouse waterfall from an earlier deployment showed stylesheet requests of **15.52 KiB** and **4.42 KiB**, with maximum critical-path latency **352 ms**. This number is **not itself measured LCP**.
- A fresh unauthenticated production check of `/access` showed **one** render-blocking stylesheet (~1,765 bytes) containing analytics/private-workspace CSS, despite the entry page using only inline styles. The deployed version and screenshot are different builds, so their waterfalls must not be equated.
- Moved workspace-only Analytics and PrivateWorkspaceControls out of `app/layout.tsx` into `app/(workspace)/layout.tsx`, preserving URL `/` and the private-auth controls. `/access` no longer inherits those imports. The local optimized build's `/access` response showed **zero CSS `<link rel="stylesheet">`** after the edit.
- Changed chart to a dynamic component in `web/ui/App.jsx` so its vendor `uplot` stylesheet stays with the on-demand chart. Kept execution-panel and position-panel CSS in the main workspace module because moving them created an extra critical stylesheet and broke direct Node component tests.
- **No preconnect hints added:** the audit found no extra useful cross-origin connection; hints to unused origins would create needless network work. Avoid blindly enabling global experimental CSS inlining, which duplicates dashboard stylesheet bytes.
- To establish real-world LCP improvement, rerun Lighthouse/Web Vitals **on the same production route, device/network preset, cache state and build**, several times. Chromium launch is restricted in the local execution sandbox, so a numeric before/after LCP claim is not made here.

## Checks and limitations

- `npm run build` (Next.js 16.4.3) — **passed**, including TypeScript build check.
- `node --test --test-reporter=dot tests/*.test.mjs` — **passed**.
- `node --import tsx --test tests/*.test.ts` — **26/26 passed**. This invocation avoids a sandbox IPC permission problem with the `tsx` CLI.
- `.venv/bin/python -m unittest discover -s tests -p 'test_*.py' -v` — **11/11 passed**, using `tools/research-requirements.txt`.
- `npm audit --omit=dev --audit-level=high` — **exit 0, no high or critical findings**; reports **two moderate** vulnerabilities involving ExcelJS's `uuid` transitive dependency. A suggested forced ExcelJS major downgrade is breaking and was not made without runtime regression testing.
- New `web/tests/access-critical-path.test.mjs` prevents reintroducing workspace-only styles into the `/access` root.
- Not executed: authenticated protected workspace journey; direct provider billing reads; real exchange order/settlement; production Lighthouse numeric LCP. These require separate access/measurements, not inference from green unit tests.
